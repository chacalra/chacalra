## Engineering approach

I prefer projects that show more than a final result.

The work I consider portfolio-ready aims to include:

- a clear problem statement;
- deliberate architecture and trade-offs;
- automated tests;
- CI where it adds real value;
- reproducible setup;
- documented limitations;
- evidence that the result can be inspected and verified.

I avoid adding tooling only for appearance. A green CI badge, a Dockerfile, or a large dependency list is useful only when it reflects an actual engineering decision.
